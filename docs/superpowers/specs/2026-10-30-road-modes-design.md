# Road modes and difficulty

Add selectable Normal (five same-direction lanes), Two-way (four lanes, two in each direction), and Opposite (three oncoming lanes). The user confirmed that all three Opposite lanes carry oncoming traffic. Reuse the current Three.js game, fleet, player models, controls and showroom. Work in the existing checkout so the user's running development server receives the changes.

A shared immutable run configuration defines lane centres, NPC direction and Easy/Medium/Hard rules. Even lane counts use half-integer lane IDs so the road remains centred. Two-way starts in the right-hand carriageway. NPCs never cross the direction divider; oncoming models face the player, use positive wheel travel magnitudes, correct local indicators and player speed plus NPC speed for closing movement. Ground traffic remains grounded. Road markings, verges, rails and gantry collision/render widths derive from the same layout.

Difficulty must change observable simulation behavior: cruising/boost speed, traffic population and spawn rate, hazard onset/frequency, driver warning/decision timing, headway, energy drain/recharge and score rewards. Keep Normal/Medium compatible with the current game. All levels retain safe starts, bounded populations, spawn clearance, warning before lane changes and physical colliders. Easier levels provide more warning, more flight energy and fewer hazards. Hard increases pressure without shrinking hitboxes or introducing unannounced cut-ins.

The main and garage Drive actions open a run-setup dialog. It offers three road choices and three difficulty choices with practical descriptions and an explicit Start action. Selection is saved; mode changes apply only in the menu. Pause/retry preserve the current immutable configuration. HUD, pause and results identify the active run. Save validated records independently for all nine combinations and migrate existing records to Normal/Medium while preserving lifetime totals.

Approach: use one shared configuration and direction-aware simulation rather than copying the game into separate mode implementations. Cache road geometry by mode rather than scaling the full scene, which would distort lane widths and player models. This is an implementation choice based on the current shared simulator and renderer.

Verify configuration validation, all lane clamps, actual oncoming closing movement and collision, direction-constrained maneuvers, swept collisions, safe generated traffic in all nine combinations, measurable difficulty differences, deterministic retry, records isolation, geometry/collider agreement, full tests and production build. Live browser checks depend on local browser access; if disabled, record the limitation and run automated geometry/HTTP checks.
